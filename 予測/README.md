# 予測フォルダ README

交通量（待ち台数・到着間隔）を GNN で予測するモデルの**学習用スクリプト**を置くフォルダ。
学習済みモデルは `予測モデル/` 以下に、学習用 CSV は `★学習用データ/` 以下に格納する。
`制御/` 側の SUMO 制御プログラムは、ここで作ったモデル（`.pth` + `scaler*.pkl`）を読み込んで動作する。

共通仕様:

- ノードは道路1〜9 の 9 ノード、エッジは `新環境_隣接行列.csv` から構築
- 対象道路ノードの特徴量のみ `ALPHA` 倍して強調
- 正規化は `MinMaxScaler`（train のみで fit → val/test に transform）
- 学習器は GCNConv 3〜5 層。★付きの現行版は「GCNConv×3 + スキップ接続 / 学習率スケジュール
  400 エポック / early stopping / RMSE が目標値未満になるまで再学習する while ループ」

### 赤2分割モデルの学習実績（2026-07-30〜31, RTX 3080 Ti）

保存済みの `予測結果_*.csv` から再計算した、テスト日1日（664サイクル）の RMSE。
「σ比」は 予測の標準偏差 ÷ 実測の標準偏差 で、1.00 に近いほど実測どおりのばらつきを再現できている。

| 出力フォルダ | 設定 | t3 | t4 | 全体 | σ比 (t3 / t4) |
| --- | --- | --- | --- | --- | --- |
| `道路1_分散評価あり` | t3・t4 の両方に分布形状損失 | 1.1911 | **1.3374** | 1.2664 | **1.00 / 0.98** |
| `道路1_分散t4のみ` | t3 は MSE+MAE のみ | **1.1093** | 1.3864 | **1.2555** | 0.89 / 1.00 |
| `道路5_分散評価あり` | t3・t4 の両方に分布形状損失 | 1.1142 | 0.7625 | 0.9547 | 0.97 / 0.97 |

読み取れること:

- **道路1 の律速は常に t4**。4試行（分散評価あり）で t4 は 1.3374〜1.3577、3試行（分散t4のみ）で
  1.3785〜1.3864 と、いずれも狭い範囲に収まる。ランダム初期化のやり直しでは頭打ち。
- **t3 の分布形状損失を外すと t3 の RMSE は下がるが（1.1911 → 1.1093）、予測のばらつきが
  実測の 89% に縮む**。分布形状損失が防いでいた「平均値寄せで誤差だけ小さくする」挙動が出た形。
  同時に胴体（GCN 3層）を共有しているため t4 は悪化する（1.3374 → 1.3864）。
  → 前半/後半の大小関係を使う信号制御用途では、σ比 1.00 の **分散評価あり** の方が安全。
- **道路5 は t3 が律速**（3試行で 1.1029 / 1.1064 / 1.1142）。t4 は 0.761〜0.763 で安定。
- さらに RMSE を下げるには再試行ではなく構成変更が要る。val Loss がスケジュール末尾
  （epoch 395）まで改善し続けていたので、`learning_rates` の延長が第一候補。

### 実行方法（★付きスクリプト共通）

```text
python ★予測モデル作成_待ち台数_赤2分割.py         # ファイル先頭のフラグ設定に従う（既定: 道路1）
python ★予測モデル作成_待ち台数_赤2分割.py 5       # 道路5 のみ学習
python ★予測モデル作成_待ち台数_赤2分割.py both    # 道路1 → 道路5 を連続学習
```

道路ごとに別フォルダへ保存されるので、連続学習しても互いに上書きされない。

## 既知の注意点

1. **到着間隔スクリプトのデータパスは修正済み。**
   以前は両スクリプトが `DATA_DIR = ★学習用データ`（直下）を見ていて FileNotFoundError になっていた。
   現在は間隔台数目の列数に合うフォルダを指すよう修正済み
   （2列版 `★予測モデル作成_到着間隔込み.py` → `3. 到着間隔_学習データ_20260627 (道路1, 5)`、
   1列版 `★予測モデル作成_待ち台数_間隔同時予測.py` → `2. 到着間隔_学習データ_20260628 (道路1)`）。
   どちらも待ち台数 130,320行 × 9列 と間隔台数目の行数が一致することを確認済み。

2. **`新環境正解データ_12.22.csv`（大小関係ラベル）は道路5・道路6 の列が信用できない。**
   待ち台数 CSV の最終日から計算した大小関係ラベルと突き合わせると、
   道路1,2,3,4,7,8,9 は 665/665（100%）一致するが、道路5 は 65.4%、道路6 は 60.6% しか一致しない
   （別定義で作られたと思われる）。
   ★赤2分割版では大小関係の正答率評価は **既定で OFF**（`EVAL_ORDER_ACC = False`）。
   評価が必要になったら `True` にすれば、**実測ベース（テストデータから算出）** と
   **正解CSVベース（旧版互換）** の両方を出力し、両者の一致率が 99% を下回ると警告する。
   その場合 **道路5・道路6 では実測ベースを見ること。**

3. **赤2分割データと赤3分割データはサイクル長が違う**（665サイクル/日 vs 812サイクル/日、
   151日 vs 181日）。スクリプト先頭の `CYCLE_LEN` / `CYCLES_PER_DAY` / `EXPECTED_DAYS` は
   データセットとセットで変更する。

4. **旧スクリプトの一部は絶対パス直書き**（`C:\Users\tslab\…` など）で、このPCでは動かない。
   現行の ★付きスクリプトはすべて `BASE_DIR`（スクリプトの置き場所）基準の相対パス。

5. **待ち台数 CSV の文字コードが混在している。**
   `新環境待ち台数データ_12.22.csv` と `赤時間3分割_統合.csv` は UTF-8、
   `待ち台数_学習データ.csv` は cp932。★赤2分割版は `utf-8-sig`（BOM 有無どちらも読める）で
   統一しているが、旧スクリプトは cp932 で読んでいるため列名が文字化けする
   （数値列だけを使うので動作自体には影響しない）。
