# 赤時間3分割GNNモデルを用いた信号制御案

## 前提

- **予測モデル**: `★予測モデル作成_待ち台数_赤3分割.py`（GCNConv×3 + スキップ接続）
  - 入力: あるサイクルの赤時間3分割の待ち台数 [t1, t2, t3]（対象道路ノードのみ ×ALPHA）
  - 出力: 次サイクルの赤時間3分割の待ち台数 [t4, t5, t6]
  - **t4 / t5 / t6 は「赤を3分割した各1/3区間の台数」**（累積ではなく区間ごとの独立値）
    - t4 = 赤の最初の1/3
    - t5 = 赤の真ん中の1/3
    - t6 = 赤の最後の1/3
  - モデル保存先: `予測モデル/3. 赤時間3分割/道路1_分散評価あり/`, `道路5_分散評価あり/`
    （分散評価あり＝分布形状損失を入れて学習したモデル）

- **改良のベース**: `制御/新環境用/3. 信号制御_mix.py` を複製して改造する
  （既存を壊さず比較できるようにする）

- **既存フレームワークで流用できるもの**（改造不要）:
  - `delta = 台数 × 2`、`±10s` クランプ（`OFFSET_ADJUST_PER_CYCLE = 10`）
  - 青時間への反映: `dur = INITIAL_PHASE_DURATIONS[0] + delta`（基本青60s）
  - サイクル長ドリフトの累積補正: 累積が `OFFSET_ADJUST_THRESHOLD = 20s` に達したら
    調整サイクルで押し戻す（`adjust_signal_A_based_on_prediction` 内）

- **改良の本体**: `calculate_prediction_delta()` を3分割ルールに差し替える。
  あわせて遅れ時間の計測部（現状「前半台数/後半台数」前提）を3分割対応に直す。

- **評価指標**: 遅れ時間（既存の計測をそのまま使用）

## 制御案1: 最大区間ベース（argmax + 非対称制御）

### 考え方

赤時間のどの1/3に台数が集中しているかで青時間を増減する。
- 前半集中 → 青を延ばして今サイクルで捌く
- 後半集中 → 青を削り、サイクルを前にずらして次サイクルの青を後続集団に合わせる
  （オフセット再整列）

### 制御則

```
seg = [t4, t5, t6]

t4 が最大（または t4 == t6 で最大） : delta = + min(t4 * 2, 10)   # 延長
t5 が最大                          : delta = 0
t6 が最大                          : delta = − min(t6 * 2, 10)   # 短縮
```

### 詰めるべき点（実装時に反映）

1. **±10s クランプ必須**: `t6 * 2` は t6=6台で12s → 上限10sに収める（上の式で対応済み）。
2. **argmax の不安定性 → デッドバンド推奨**:
   `t4=5,t5=4,t6=4` と `t4=4,t5=5,t6=4` が1台差で +10s↔0s と急変する。
   「最大 − 2番目 < マージン(初期値2台)」なら `delta = 0` として境界のガタつきを抑える。
3. **後半集中(t6)の遅れ悪化リスク**: t6の車を次サイクルに回すと、その車の遅れは
   約1サイクル分増える。効果が出るのは交差点Jが上流と連動している場合。
   → 遅れ時間を「全体」と「t6で回された分」の両方で計測し、効果を切り分ける。

## 制御案2: 3分割 重み付き需要応答（延長方向）

### 考え方

赤時間3分割に重みを付けた「重み付き需要」を作り、基本青が捌ける基準台数との差で
青時間を増減する。後半に残る車ほど次青で捌く必要が高い、という重み付けが可能。

### 制御則

```
W_weighted = t4 * w4 + t5 * w5 + t6 * w6      # 重み付き需要（初期例 w4=0.5, w5=1.0, w6=1.5）
delta = clamp( (W_weighted − W_ref) * 2, −10, +10 )
```

- `W_ref` = 学習データから求めた**サイクル需要の中央値**（道路ごと）
- 予測需要が基準より多ければ延長(+)、少なければ短縮(−)

#### W_ref の決定（2026-07-23 確定）

学習データ `赤時間3分割_統合.csv`（全146,972サイクル、1サイクル=3行）を道路ごとに
サイクル単位へ整形し、`t4+t5+t6` の**中央値**を基準点とする。train170日でも同値。

| 道路 | W_ref（合計の中央値） | 各区間の中央値 t4/t5/t6 | 平均 | 分位点 25/50/75/99% |
|---|---|---|---|---|
| 道路1 | **5** | 1 / 1 / 2 | 4.57 | 2 / 5 / 6 / 12 |
| 道路5 | **2** | 1 / 0 / 0 | 2.49 | 1 / 2 / 4 / 9 |

- 中央値を採用した根拠: 道路1は平均<中央値(左寄り)、道路5は平均>中央値(右寄り)と
  歪みの向きが逆で、平均だと道路ごとにズレ方が異なる。中央値は両方に無難。
- **注意**: 上は重みなし合計の中央値。重み `w4/w5/w6` を最終決定したら、その重みでの
  「重み付き需要のサイクル別分布」から中央値を取り直すこと（中央値は非線形）。
  参考: 重み例(0.5/1.0/1.5)での重み付き中央値は 道路1=5.00 / 道路5=2.00 で偶然一致した。
- 計算スクリプトは会話ログの手順を流用（df をサイクル単位に reshape(-1,3) して median）。

### 懸念と解決（重要）

- **懸念**: 単純に `delta = W_weighted * 2` とすると台数も重みも正なので
  **delta が常に正**になり、`cumulative_control` が一方向に溜まって
  調整サイクルが多発する。
- **解決**: 上の式のように **基準 `W_ref` を引いて** delta を正負両方に振れるようにする。
  平常時は delta が0付近で振れ、累積が一方向に溜まらない。
- （補足）重みを符号付き `w4=+1, w5=0, w6=−1` にすると `delta ≈ (t4−t6)*2` となり
  案1の連続版に収束する。案2を「延長方向の需要応答」として残すなら基準引き方式が素直。

### 重み（2026-07-23 確定: A・B の2つを実装して遅れ時間で比較）

| 案 | w4/w5/w6 | 狙い | W_ref 道路1 | W_ref 道路5 |
|---|---|---|---|---|
| A | 1.5 / 1.0 / 0.5（前半重視） | 長く待つ車を優先（累積待ち時間） | 4.0 | 2.5 |
| B | 0.5 / 1.0 / 1.5（後半重視） | 積み残しを防ぐ（末尾を捌く） | 5.0 | 2.0 |

- 重みは合計3に正規化済み（W_weighted のスケールを重みなし合計と揃える）。
- W_ref は各重みでの「重み付き需要のサイクル別分布」の中央値（学習データ全体）。
- delta が ±10 クランプに達している範囲では重みの向きは結果に効かない。
  効くのは中程度需要の範囲のみ。→ 最終判断は遅れ時間の実測。

## 計測・サイクル長・比較設定（2026-07-23 確定）

参照元プログラム: `C:\Users\Tsukasa\Desktop\研究\計測\プログラム\計測\★赤時間3分割計測_北南20%削減全日_2026-07-17.py`
このプログラムの「時間帯別サイクル長」「赤3分割の計測方法」を採用する。

### サイクル長（時間帯別）

- BASE_CYCLE_LENGTH=120（net.xml現行）、PREP_CYCLE_LENGTH=100、warmup=1200s。
- `build_scaled_logic`: 黄・全赤・右折矢印(10s未満)は固定、10s以上の青フェーズに
  ΔC を均等配分してサイクル長を作る。全120s信号に適用。フェーズ番号・状態は不変。
- 時間帯別目標サイクル長 `CYCLE_SCHEDULE_BY_HOUR`:

| 時間帯 | サイクル長 |
|---|---|
| 準備(warmup) | 100s |
| 0〜7時 | 100s |
| 7〜8時(朝ピーク) | 130s |
| 8〜17時 | 110s |
| 17〜19時(夕ピーク) | 130s |
| 19〜24時 | 100s |

### 制御 delta とサイクル長の共存（確定）

- delta は「時間帯スケジュールでスケールした青」に加算する（固定60/26ではない）。
- J交差点のみGNN制御。累積補正（閾値20s）は、Jのサイクル長を**その時間帯の
  目標サイクル長へ戻す**方向に働く。→ Jは一時的にスケジュールからずれるが有界。
- 対象フェーズは参照プログラムの `ROAD_PHASE_TARGETS` に合わせる:
  **道路1 green=0/yellow=1、道路5 green=5/yellow=6**。
  （注意: 旧 `3. 信号制御_mix.py` は道路5を phase6 で扱っていた。参照プログラム側が
  学習データ生成と同じなので、そちらに統一する。）

### モデル入力 t1,t2,t3 の計測（学習と一致させる・必須）

- 赤サイクル=黄終了〜次の青開始。赤中に各車が**初めて停車した時刻**(speed≤0)を記録し、
  赤終了時に赤時間を3等分してビン分け。**全道路 ÷2（ceil）**。
- 学習データ `赤時間3分割_統合.csv` はこの方法で作られている。制御の入力計測も
  同一にしないと分布がズレる。

#### ★重要な発見（2026-07-23）: 既存制御の計測は「別物」で流用不可

`3. 信号制御_mix.py` の制御対象道路計測（`j_road_red_history`）は、赤中の**各ステップの
停車台数＝待ち行列長（累積）**を記録し、50%/100%点の値で前半/後半を作っている。
一方、赤3分割モデルの学習データは**各車の初停車時刻を3区間にビン分けした台数（非累積）**。
**この2つは別量**。待ち行列長をそのまま入れると学習時と分布が変わり予測がずれる。
→ 計測部は「初停車ビン(3分割)・全9道路」へ**作り替えが必須**（計測プログラムの
   `record_stops` + `write_red_split` を移植）。ここが実装の主要工数。

- モデル入力は **全9道路** の [t1,t2,t3]（[9,3]）が必要（学習の build_daywise_dataset と同じ）。
  → 制御対象(1/5)だけでなく全9道路で3分割を計測する必要がある。
- 制御対象道路の赤検知は既にフェーズ遷移ベースで動的（可変サイクル長に対応）なので、
  そのタイミング枠組みは流用でき、「記録する量」を待ち行列長→初停車ビンに変えるのが要点。

### 比較指標と遅れ計測方法（確定）

- 比較指標: **待ち台数** と **遅れ時間**（従来と同様）。
- 遅れ計測は既存制御プログラムと同じ方式・同じ信号機・同じまとめ方を採用:
  - 各道路のエッジ上で毎ステップ speed≤0 の車を「停車」とみなす。
  - その車の停車秒数を `vehicle_delay_time[veh] += 1`（1ステップ=1秒）で累積。
  - サイクルごとに、停車車両数=**待ち台数**、その停車秒数の総和=**遅れ時間(秒)**。
  - 交差点別に集計（既存の `交差点別_待ち台数_遅れ時間_集計.csv` と同じまとめ方）。
    対象信号は既存プログラムと同じ（TL_ORDER: P,O,N,M,J,F,E,D,A ほか、各交差点の
    監視道路）。各信号機ごとの遅れ内訳＋全体合計を出す。

### 集計の時間窓（2026-07-23 追加）

- 車両データは24時間分。全24hに加え、**6〜19時のみに絞った集計**も出力する。
- 実装: `summarize_time_window()`。per-cycle の queue_delay ログ（vehicle_delay_time方式の
  待ち台数・遅れ時間）を step→時刻(`hour=(step-PREP_TIME)/3600`)に変換し、
  `ANALYSIS_START_HOUR=6, ANALYSIS_END_HOUR=19`（半開 [6,19)）で絞る。
- 出力: `<OUT_DIR>/時間窓別集計_全24h_と_6-19時.csv`（全道路(J:1/5/6/10)＋道路別、
  窓ごとにサイクル数・待ち台数合計/平均・遅れ時間合計/平均）。
- ※ 現状この集計はJ交差点の道路(1/5/6/10)が対象。A〜P全体の時間窓集計が要る場合は
  per-signal遅れ計測をA〜Pに拡張してから同様に窓を適用する。
